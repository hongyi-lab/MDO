# CFD × Foundation Model 实验协议 v1

**协议编号：CFD-FM-v1｜冻结日期：2026-09-25｜适用硬件：单张 RTX A6000 48 GB。**

先回答核心问题：**可以在服务器上用 AeroTransformer Large，再用作者公开的 CRMpert CFD 真值微调；不需要自己先生成几百个 CFD，也不需要重新预训练。** 本轮检验“换大模型、做微调后，是否更准确、校准区间是否足够窄”。真正的 CFD 加速另需同几何、同物理条件的现场计时。

本文是正式实验前的约定，不是实验结果。配套 [固定样本清单](../configs/protocol_v1_split.json) 已生成并检查；**当前旧版 `run_validation.sh` 仍是 72 样本 pilot，尚不能执行本文完整四分组流程。** 不要把本协议 JSON 直接当作旧脚本的配置。

## 1. 本轮具体要回答什么

| 问题 | 对照 | 判断依据 |
|---|---|---|
| Large 本身是否优于 Small？ | S-zero 与 L-zero | 同一测试集上的气动力、表面场误差与延迟 |
| 微调能否缩小精度差距？ | L-zero、L-head、L-full | 同一 450 训练样本；开发集选超参；独立测试 |
| 改善究竟来自容量还是微调？ | S-full 与 L-full，并结合两个 zero | 相同数据、预算、学习率候选和评价规则 |
| 能否放心少跑 CFD？ | 每个模型的独立校准与放行结果 | 联合 CL/CD 区间、覆盖率、错误放行、回退比例 |
| 是否真的省时间？ | 同一新案例的 FM 与真实 CFD | 精度成立后，再比较含回退及离线成本的耗时 |

第一阶段只处理机翼表面 `Cp/Cf` 和积分气动力，不要求完整体积流场。压力载荷向结构网格的保守映射、几何导数、气动弹性耦合与完整 MDO 优化另设验收；**CL/CD 合格不等于这些接口已经合格。**

两条证据线分开报告：

- **A：公开数据适配。** CRMpert 的 CFD 标签作为参考；验证 Large 和微调的作用。能够测模型延迟，不能凭标签文件给出 CFD 加速倍数。
- **B：现场 CFD 对照。** 同一明确几何、工况、表面范围及积分定义，实际运行 ADflow，验证新场景精度和成本。A 的置信区间不能直接搬给 B。

## 2. 微调的数据从哪里来

数据是作者公开的 [CRMpert 固定版本](https://huggingface.co/datasets/thuerey-group/CRMpert/tree/88ece28b846fd1d9870933252db556cf97d30ae0)：**288 个机翼几何、2145 个流动工况，每个几何 3–8 个工况**。标签来自 CFD，包括表面压力、摩擦和气动力；不是我们拿 FM 自己预测出来的伪标签。

预训练权重来自 [AeroTransformer 固定版本](https://huggingface.co/thuerey-group/AeroTransformer/tree/698d70095a00d6f4a25f870e8de0772fc12b68f7)。作者先在 SuperWing 的 4239 个几何、28,856 个 CFD 工况上预训练，然后研究向 CRMpert 等任务的迁移。**SuperWing 是预训练数据；CRMpert 是我们这次使用的目标域数据。** 公开资料的任务划分不能替代逐几何重合审计，后者尚未完成。[论文与数据说明](https://arxiv.org/html/2604.18062v1)

实际数据链路：

```text
作者预训练权重                 作者公开 CRMpert 的真实 CFD 标签
        │                                  │
        └── 初始模型 ── 450 个训练工况 ── 微调模型
                                        │
                           开发集选学习率 → 锁定权重
                                        │
                            校准集定区间 → 测试集验收
```

四个核心数组全部下载约 **2.143 GB**；Large 权重文件 **58,218,804 bytes，约 58.2 MB**。无需下载 TB 级 SuperWing，也无需生成新的 450 个 CFD 算例。复用公开数据意味着本轮新增标签生成费用为零，**不意味着这些标签原本没有 CFD 成本**。

如果下一步适配的是不同机翼族、网格约定、Re 或求解器，必须用该任务自己的 CFD 标签重新做训练/校准/测试。先冻结新几何及工况清单，再求解；不把新案例混回本轮测试集，也不把旧校准结果当成新场景可靠性证据。

## 3. 数据划分：按机翼隔离，四组各司其职

### 3.1 已冻结的数量

| 分组 | 几何数 | 使用的流动工况数 | 唯一用途 |
|---|---:|---:|---|
| Train | 144 | **450** | 梯度更新、训练输入支持范围 |
| Dev | 48 | **350** | 学习率选择；正式测试前的开发诊断 |
| Calibration | 48 | **359** | 权重锁定后计算置信区间 |
| Test | 48 | **360** | 所有方案锁定后的一次性验收 |
| Train 内未选工况 | 同属上述 144 个几何 | 626 | v1 不使用、不额外调参 |

全部 288 个几何只属于一组。同一机翼的不同 Mach/AoA **不得跨组**。校准和测试均使用该组机翼的全部公开工况，避免每组挑选难度不同的条件。

“450 样本微调”指 **450 个训练工况，不是 450 个机翼，更不是整个研究只用了 450 个标签**。本轮合计会使用 **1519 个公开标签**，其中 1069 个用于开发、校准和测试；成本表分别记账。

### 3.2 先前看过的数据如何处理

此前 72 样本 pilot 与最早 8 样本安装检查合计暴露了 **77 个不同机翼、77 个工况**。早期 8 样本额外暴露的几何 ID 为 `41, 82, 123, 164, 205`。它们全部归入 Train；77 个已看过的标签全部计入 450 个训练预算。

旧 pilot 的 test 已被用于讨论改进方向，因此现在只能叫探索结果，不再是正式实验的全新测试集。除上述暴露记录外，若发现其他历史标签查看记录，应在任何正式测试前修订清单并升版；不得隐瞒。

### 3.3 选择算法与唯一清单

样本 ID 是原始完整 `index.npy` 的 **零基行号**，不是下载子集的局部行号。完整清单见 [protocol_v1_split.json](../configs/protocol_v1_split.json)，其 SHA-256 为：

```text
e673863692913f4fdf09982cae3a44f402c379ee596ceba463ac12d0eece6c8f
```

划分仅使用元数据和历史暴露记录，不读取新的场标签或预测误差：

1. 将未暴露的 211 个几何按 `SHA256(UTF8("CFD-FM-v1|split|20260925|shape:" + 十进制几何ID))` 升序排列；前 67 个补入 Train，随后依次取 48 个 Dev、48 个 Calibration、48 个 Test。
2. 训练选择先纳入已暴露的 77 个工况，再为其余 67 个训练几何各选一个工况。
3. 几何按 `SHA256("CFD-FM-v1|train|shape:{g}")` 排序；同几何工况按 `SHA256("CFD-FM-v1|train|sample:{i}")` 排序。逐几何轮流加入尚未选中的工况，直到 450 个。最终保存数值排序后的 ID。
4. 三个 holdout 分组均取其几何下全部公开工况。随机训练种子不改变划分，也不重新抽 450 个样本。

训练/选参阶段的数据加载器只能返回 Train/Dev 的场标签。下载文件落盘不等于测试已完成，但不能让开发报告提前计算或显示 Calibration/Test 标签和误差。校准之后不再改权重；看过正式测试后再改模型，后续结果必须标成后验探索或另开新测试集。

## 4. 输入输出及物理约定

| 项目 | v1 固定约定 |
|---|---|
| 几何输入 | 表面单元中心，`3 × 128 × 256`；沿用发布数据的单位和姿态，不新增任意缩放、旋转或归一化 |
| 积分几何 | 配套原始表面顶点 `3 × 129 × 257`，不可用中心点假装顶点 |
| 工况输入 | `[AoA_deg, Mach]`，直接读取 `index[:, 2:4]` |
| 坐标方向 | `x` 流向、`y` 竖向、`z` 展向，沿用作者实现 |
| 物理范围 | 本轮按发布任务固定 Re = `2e7`、T = `300 K`、RANS/SA；不把两个输入条件的模型宣称成可变 Re/T/湍流模型 |
| 训练输出 | `[Cp, 150 × Cf_stream, 300 × Cf_span]`，不再额外标准化 |
| 展示及场误差 | `Cf_stream` 除以 150，`Cf_span` 除以 300，恢复物理系数后计算 |
| CL/CD 主参考 | `index[:, 9:12]` 中作者重新表面积分所得系数，采用固定 floGen/cfdpost 积分实现 |
| 原求解器系数 | `index[:, 6:9]`，仅单独诊断；不得混作上述主指标的真值 |
| CM | 仅诊断；数据说明与积分实现的力矩参考点存在需核对事项，暂不作为放行指标 |

元数据中 AoA 约为 **4.718–10.712°**、Mach 约为 **0.75004–0.89977**；论文描述的相对安装角扰动与这里保存的 AoA 不是直接可互换的数。**不要擅自减去 6.71°**，否则几何姿态与输入工况会不配套。这些全数据范围仅说明数据，不用于扩大训练支持范围。

字段缺失、单位不明、网格尺寸错误、非有限数、Re/T 或表面定义不匹配：拒绝直接放行，记录原因。禁止静默补工况，禁止把失败工况从分母删掉。

## 5. 模型、微调方式与训练参数

### 5.1 固定对照矩阵

| 名称 | 起点 | 更新哪些参数 | 训练标签 | 用途 |
|---|---|---|---:|---|
| S-zero | 官方 ATsurf_S | 无 | 0 | 已有小模型基线 |
| L-zero | 官方 ATsurf_L | 无 | 0 | 仅增加模型容量 |
| S-full | 官方 ATsurf_S | 全参数 | 450 | 分辨大模型和微调的各自贡献 |
| L-head | 官方 ATsurf_L | `final_layer.out_proj` | 450 | 最便宜的输出层适配 |
| **L-full** | 官方 ATsurf_L | 全参数 | 450 | **预先指定的主候选** |

Large 按公开配置实际统计为 **14,517,280 参数**；L-head 为 **55,344 参数，约 0.381%**。这里的 head 是原模型最后的 `3×3` 卷积投影，不是 LoRA，也不是论文中的 QKV-only。保留官方架构；v1 不增加新的 encoder/decoder。

### 5.2 固定训练参数

| 参数 | 约定 |
|---|---|
| 优化器 | Adam，`betas=(0.9,0.999)`，`eps=1e-8`，`weight_decay=0` |
| 学习率候选 | `{1e-5, 1e-4}`，每种微调方案分别选；常数学习率，无 scheduler |
| 训练量 | 每次 450 工况，30 epochs，batch size = 1，共 **13,500 次更新** |
| 损失 | 三个已缩放表面通道和所有节点的等权 MSE；不含额外系数损失或物理损失 |
| 精度 | FP32，关闭 AMP、TF32；不使用量化 |
| 梯度裁剪 | 全部可训练参数的 L2 norm 上限 1.0 |
| 数据顺序 | 每 epoch 使用固定种子的置乱；无数据增强，无梯度累积 |
| 训练种子 | `7, 17, 27`；同时固定 Python、NumPy、Torch/CUDA |
| checkpoint | **第 30 轮最后权重**；不早停，不看校准/测试挑 epoch |
| 初始化 | 每次均从同一官方 checkpoint 开始，不接着上次试验训练 |
| head 模式 | 主干参数冻结且主干 eval；核验冻结参数和缓冲区未改变 |
| 复现设置 | `cudnn.benchmark=False`，确定性算法开启；不支持时显式失败并记录，不能静默换设置 |

先用 seed 7 跑 **3 种微调方式 × 2 个学习率 = 6 次**。每种方式只按 Dev 选择学习率，评分为：

```text
J_dev = max(几何宏平均 CL_MAE / 0.01,
            几何宏平均 CD_MAE / 0.0005)
```

选最小 J；完全相同时选较小的物理 Cp_RMSE，再相同时选较小学习率。不因为校准 q 不好而重选。随后各方式以所选学习率再跑 seed 17、27，共增加 6 次；**总计 12 次训练，162,000 次更新**。seed 7 已完成的选中权重复用，另三个落选候选保留日志但不进入正式测试。

最终每种微调方式报告 3 个种子的全部结果及均值/标准差，不挑最好种子。主可靠性检验预先指定 **L-full、seed 7**；17/27 为稳定性检查，各自独立校准。zero 模型确定性评价一次，不伪造三次独立模型重复。

这是我们的受控适配基线，**不是论文训练设置的原样复现**。论文采用不同验证/训练安排，正文和公开训练脚本的优化器描述亦有差别；不能将我们的误差直接称为超过论文。论文正文与表格的 Large 参数量也不完全一致，本文采用固定配置实际计数。[论文](https://arxiv.org/html/2604.18062v1)；[公开微调脚本](https://github.com/tum-pbs/AeroTransformer/blob/3dc350ff69e354d1451eae468c686a368bd6151f/training/finetune.py)

## 6. A6000 上如何安排，先不猜耗时

Large 只有约 1452 万参数，单 A6000 是合理的微调设备。FP32 的参数、梯度及两组 Adam 状态合计约 232 MB，**这不包含激活、算子工作区和缓存，不能拿它当实际显存峰值**。450 个 FP32 训练样本按现加载方式约占 354 MB CPU 内存。

正式训练前只使用 Train，做 5 次预热更新和 20 次计时更新，记录 CUDA 的峰值 `allocated/reserved`、CPU RSS、单步中位数与 P95。探测权重全部丢弃，正式实验重新加载官方权重。OOM 或非确定性算子失败则先修订实现/协议，不自动降精度或偷换 batch size。

CPU 线程固定为 4，GPU 独占训练进程；记录 Xorg 和其他进程占用。现有 bootstrap 使用 PyTorch 2.11.0/cu128；驱动显示 CUDA 13.0 不代表需要安装 CUDA 13 工具包或重装驱动。记录实际 Python/Torch/CUDA/cuDNN、GPU、驱动、容器及依赖版本。实验期间不升级依赖。

预计训练成本用实测单步耗时乘更新数，另外计数据加载、评估、导出时间。前述 12 次训练是预算上限，先跑两个 zero 和 L-full 的 seed-7 两个候选，**此时仅在 Dev 上比较**，即可判断是否值得继续；zero 的 Test 结果同样留到最终统一验收。提前停止必须记为未完成，不能把少数最好结果当 full experiment。

公开数据阶段至少预留 20 GB 项目空间，数据只保留一份；失败记录、候选权重、日志按 run ID 保存。现场 CFD 阶段另预留至少 50 GB，监测实际网格/输出增长；不清理用户已有数据。服务器 `/srv` 已使用约 90%，避免下载完整 SuperWing 或反复复制数据。

## 7. 精度指标与汇总方式

设机翼 g 有 n_g 个工况。每个机翼先独立汇总，再对机翼等权平均，避免工况多的机翼权重过大。

| 指标 | 精确定义/汇总 |
|---|---|
| CL/CD macro-MAE | `mean_g(mean_j(abs(error_gj)))`，主指标 |
| CL/CD macro-RMSE | `sqrt(mean_g(mean_j(error_gj**2)))` |
| 尾部误差 | 每个机翼先取最坏工况绝对误差，报告其 P95（最近秩 `ceil(0.95*G)`）和全局最大值 |
| Drag counts | `1 count = 1e-4 CD`，绝对误差与区间半宽统一同时报 counts |
| Cp/Cf RMSE | 先每个工况按节点计算物理通道 RMSE，再工况内、几何间平均；三个通道分开 |
| 相对 L2 | 每工况 `norm(pred-truth)/norm(truth)`；真值范数 ≤ `1e-12` 则记 NA 并报数量，禁止填 0 |
| Micro 指标 | 可补充所有工况等权结果，但明确标注，不能与 macro 混比 |

同时保存逐工况预测、标签、原始误差和原始耗时，便于复核。场误差采用当前网格节点等权，不冒充连续面积加权范数。

置信门槛固定为 **CL 区间半宽 ≤ 0.01、CD 区间半宽 ≤ 0.0005（5 counts）**。这些是本项目的探索门槛，非航空工业通用标准；后续接入 MDO 要依据约束裕量、网格/求解误差和载荷敏感性重新立项验收，不能在本轮看完测试后放宽。

Cp/Cf 保留为强制报告的诊断项，目前没有经工程论证的验收阈值；因此本轮即使 CL/CD 放行，也只能说明气动力层面的可行性，不能声称整个表面载荷场已达到替代标准。

报告图固定为：系数 parity、各机翼绝对误差、联合区间与回退、Cp/Cf 真值/预测/误差、延迟分布。详细案例按几何最坏 CD 误差排序，展示最差、中位和最好案例，平局按 ID；注明这是测试后的展示选择，不用于改模型。所有案例可查，CFD 与预测共用色轴（Cp 默认为 `[-1.5,0.8]`，超界明确标记），误差图单独色轴。

## 8. 置信度：只校准一次，明确那个共同的 q

权重、预处理、积分实现和 Dev 决策全部锁定后，用 Calibration 的 48 个机翼计算：

```text
s_g = max_{该机翼全部公开工况 j} max(
        abs(CL_pred - CL_ref) / 0.01,
        abs(CD_pred - CD_ref) / 0.0005)

alpha = 0.10
rank = ceil((48 + 1) × (1 - alpha)) = 45
q = 48 个 s_g 从小到大排序后的第 45 个值，不做插值

CL 区间 = CL_pred ± q × 0.01
CD 区间 = CD_pred ± q × 0.0005
```

**q 是共同的联合倍率**。此前 CL 和 CD 都出现 2.82 倍，是这个构造的结果，不是两个指标独立测出了相同误差。报告只列一次 q，再列两个物理单位的区间半宽。

每个固定 checkpoint 独立得到自己的 q，绝不根据 q 挑模型。可预先附报 95% 区间（第 47 个值），但主结论仍按 90% 协议；不得看结果后切换置信水平。分别校准 CL/CD 可用于诊断，不能用两个单独 90% 区间冒充联合 90%。

放行同时要求：模型/数据/预处理/积分/划分身份一致；输入完整且物理定义匹配；预测和 q 有限；位于训练支持范围；**q ≤ 1**。支持范围只从 450 个 Train 工况计算：AoA、Mach、x/y/z extent、协方差小/大及中/大特征值比，各取训练最小值至最大值，**无扩边**。这是粗筛，不是全面 OOD 识别。

当前 q 是全局值：若 q > 1，所有查询都不能通过这一宽度条件，即使平均误差很好。若 q ≤ 1，仍可能因 OOD 或身份不一致被拒绝。推理路由不得读测试真值；真实 CFD 后端缺失时状态必须是 `CFD_required`，不能用公开标签装成已执行回退。

必须同时报告：

- **组覆盖率**：Test 48 个机翼中，所有已列工况的 CL/CD 同时被区间覆盖的比例。不能把 360 个相关工况当 360 个独立机翼。
- **放行率**：按工况计通过门控的比例；另报至少有一个放行工况的几何数。
- **错误放行**：放行工况里实际任一误差超过 CL/CD 容差的比例，以及至少发生一次错误放行的几何数。分母为零时记 NA。
- 所有模型的组覆盖率给出 95% Wilson 区间；预先指定主模型另给出一侧 95% 精确二项覆盖率下界及错误放行率上界，且注明独立同分布几何假设。错误放行上界按 `K_A / N_A` 计算：`N_A` 是至少有一个放行工况的几何数，`K_A` 是其中至少发生一次错误放行的几何数；`N_A=0` 时记 NA。工况级错误放行比例仅作描述，不当作独立二项试验。

Conformal 的名义覆盖依赖几何组可交换性；这里只针对“同类新机翼及其相同采样规则的工况集合”，不保证任意新工况、每个查询或经过 OOD 门控后的接受子集覆盖。**CL/CD 的区间也不是 Cp/Cf 场区间。** [Conformal 方法依据](https://arxiv.org/abs/2107.07511)；[二项区间说明](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

样本量边界：48 个独立测试机翼中至少 47 个完整覆盖，一侧 95% 精确下界才高于 90%；即使 **48 个机翼均有放行工况且没有任何错误放行**，几何级错误放行概率的一侧 95% 上界仍约 **6.05%**。接受子集更小时证据更弱；全部回退不是零风险证据。本轮不能证明“精度和置信度绝不下降”，也不能认证错误率低于 5%。

## 9. 计时：模型很快与整体加速分开

### 9.1 A 线模型延迟

在同一 A6000、FP32、batch=1、单请求串行下测试。每个 checkpoint 先用固定训练样本预热 10 次，再把 Test 360 个工况按源 ID 升序完整跑 5 遍。`eval + inference_mode`，CUDA 在计时边界同步，禁止用异步提交时间冒充完成时间。

分别记录：CPU 输入准备；CPU→GPU 传输及模型前向；GPU→CPU 与表面场/系数后处理；含校验及置信门控的完整在线查询。端到端时间优先；排除模型加载和磁盘读取，并另外报告冷启动。相同输入格式、相同输出交付，不能拿只生成 tensor 的 FM 与完整 CFD 报告相比。

每工况先汇总 5 次中位数，再报告 360 个工况的延迟中位数/P95；吞吐 = 总查询数/总实测时长。计时循环不重复选择模型，不把重复计时当新增独立精度样本。若实现尚未测到门控段，必须标注为“预测接口耗时”，不得标成完整在线查询。

### 9.2 B 线真实 CFD 与成本

本轮现有新几何案例仅用于打通安装和接口。它不是 CRMpert 原算例复刻；现配置 AoA = 2°，也不在上述发布数据的输入范围内。**不要用这个调试算例直接宣布 CRMpert 模型分布内精度或可靠性。**

在取得第一条正式 CFD 对照结果前另冻结 `CFD-FM-v1B` 案例清单：几何、采样、姿态/AoA、Mach/Re/T、表面族、参考面积/长度、压力基准、摩擦方向和力矩参考点逐项配套；生成 request/hash 后不得改完几何仍沿用旧结果。它是 A 线后的独立阶段，不混入 A 线排行榜。

| 项目 | B 线初始固定设置及使用边界 |
|---|---|
| 求解器 | 官方 MACH-Aero/ADflow 容器，运行前记录不可变 image digest，RANS/SA |
| CPU | 8 MPI ranks，`OMP_NUM_THREADS=1`；记录实际核绑定；与 GPU 训练分时运行 |
| 收敛 | `L2Convergence=1e-10`、`nCycles=3000`；现实现检查残差、失败标志及有限数。系数稳定性的统计窗口、CL/CD 波动容差须在 v1B 实跑前另行冻结并实现，不能把它说成现有检查 |
| 网格 | 原生 81 层，当前开发几何估计约 352.8 万单元；41 层仅安装调试 |
| 网格敏感性 | 至少有一个更细网格，明确壁法向与表面/尾迹分辨率；单改法向层数不等于完整网格无关性验证 |
| 数值误差预算 | 探索要求细化导致 CL 变化 ≤ 0.002、CD ≤ 1 count；达不到则参考 CFD 未过关，不硬算 FM 优劣 |
| 表面范围 | 与 FM 一致的 `mainwing` 家族；不能用总壁面系数替代主翼表面系数 |
| 场与积分 | 先验证单位/压力基准/方向及离散积分差异；完整结构载荷替代仍需要保守场映射 |
| 计时 | 固定网格下 3 次冷启动求解，记录初始化、求解、后处理各段及总耗时；网格生成成本另列 |

单纯收敛或两张网格接近不构成工业认证。正式 CFD 定义、映射或分布变化后，需要新的独立校准；不能拿 A 的 q 证明 B 合格。

成本表至少包含下载/准备、目标域标签生成、训练、Dev/Calibration 评估、模型加载、在线查询、CFD 回退、失败重跑。CPU core-hours 与 GPU-hours 分别列，不直接当同一种成本相加。

```text
纯 CFD 在线时间 = 所有相同查询的真实 CFD 总时间
混合在线时间 = 所有查询的 FM+门控时间 + 被拒绝查询的真实 CFD 时间
在线加速比 = 纯 CFD 在线时间 / 混合在线时间

项目累计时间 = 离线数据/训练/校准成本 + 混合在线时间
回本查询数 ≈ 离线新增成本 / (单次纯 CFD 时间 - 单次混合平均时间)
```

若分母非正，则没有该定义下的回本点；查询数不足以摊薄离线成本时同样如实报告。没有实际执行 CFD 的结果，速度比填 `unverified`，不能填 0、无穷大，或引用其他论文的 16 万 CPU hours 来当我们这一例的分母。

## 10. 如何判断要不要继续接 MDO

| 观察 | 行动/允许的结论 |
|---|---|
| Large/微调改善均值，但 q > 1 | 有适配效果，尚不能按本门槛替代；分析开发集尾部，不放宽已冻结测试门槛 |
| 主模型 q ≤ 1，但支持范围内放行很少 | 精度有希望，实用性不足；报告回退率，不只展示 FM 延迟 |
| q ≤ 1、测试工况放行率 ≥ 50%、主模型覆盖数 ≥ 47/48 | 达到本项目推进现场 CFD 验证的探索条件；仍报告区间、错误放行和其他种子结果 |
| 其他种子 q 或尾部误差明显变差 | 报告不稳定；不得只以 seed 7 宣称微调普遍有效 |
| 现场 CFD 参考合格、定义配套，且混合/累计时间确实下降 | 可以主张指定场景下的加速，再做载荷映射、梯度和 MDO 耦合验证 |

50% 放行率是项目投入的实用性门槛，不是统计定理。47/48 规则针对预先指定主模型和 IID 几何假设，不能用多模型挑最好结果来套；达到它也不保证放行子集的错误率。未达标不是白做：可以定位容量、训练样本量、场损失与积分指标不一致、域差异或参考定义问题，但新方案应登记为下一轮。
