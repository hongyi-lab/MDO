## 现有结构代码是否能直接接上

`MDO/src/mdo_demo/physics_losses.py` 计算无量纲表面力积分和展向载荷；`solver.py` 是气动场/系数服务与受检查的CFD回退入口；`screening.py` 是有限气动候选筛选。这个仓库没有结构求解器、CFD/FM到结构节点的力/力矩映射、位移回传或气动弹性迭代。

工作区另一份 `RapidProcessDesign-bwb-engineering-demo/demos/bwb-flow/engine.py` 并非只有框图：`thinwall_section` / `section_at` 确实计算薄壁截面，`beam_response` / `solve_structure` 确实由截面EI和外载计算外翼弯矩、应力及挠度。它可作为低阶结构模块的实现参考，但当前 `build_load_case` 仍生成**预设椭圆升力**，结构检查针对该载荷的根部合力/弯矩。它没有接收 CRMpert/ADflow 表面场，也没有气动变形反馈；缺少扭转、屈曲和中央机体。其 BWB 几何/材料假设与轴约定也不能直接移植：该demo展向为y、竖向为z，FM展向为z、竖向为y。

因此，已有真实低阶梁方程代码可参考，但**没有可直接启动的 CFD/FM 气动—结构基线**。该demo自己的候选表、演示可行性和任务求解时间不能充作本项目的MDO实验结果。

## 最小而不虚构的下一步

1. 冻结一个机翼任务、少量twist/厚度变量、材料与结构边界；不扩展整机。气动求值与结构模型必须共享同一设计几何及一致单位。
2. 先建立固定设计的真实载荷→结构响应接口：压力/摩擦转有量纲力与力矩，映射到共用结构网格；检查总力、根部弯矩以及结构网格收敛。可用保存的CFD/模型场做传递诊断，但这不是新的CFD求解，也不是优化成绩。
3. 最小第一阶段可明确设为**单向气动—结构优化**：气动载荷影响厚度尺寸/质量、应力和挠度，双方共用结构模型和优化器。只有接好位移回传、网格变形及耦合收敛后，才升级为双向气动弹性MDO；弯曲demo本身不足以提供扭转耦合。
4. 当前原生CFD收敛与坐标/迎角/采样接口仍是实测对比的前置缺口。解决后，才在相同预算下运行 CFD-driven 与 FM-assisted 两条设计路径，使用统一复核的目标/约束及含失败、回退、复核的总时间作主图。离线训练成本另列。

今天可交付的是现有组件证据及可绘图源表；最终 MDO 目标—时间曲线当前没有真实数据，不能补画推测曲线。
